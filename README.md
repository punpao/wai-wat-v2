# กาลวัฒ (Kala-Wat)

ต้นแบบ (prototype) สำหรับ **Moral Hackathon 2026** — แอปมือถือที่พาเดินชมสถานที่จริง
โดยมี **ปราชญ์ในชุมชนเป็นคนเล่าเอง** ผ่านจอ แทนที่จะอ่านป้ายนิ่ง ๆ ข้างวัตถุ

สถานที่ต้นแบบคือ **วัดขนอน อ.โพธาราม จ.ราชบุรี** ซึ่งเก็บตัวหนังใหญ่ดั้งเดิมสมัยรัชกาลที่ ๕
ไว้ ๓๑๓ ตัว และยังมีคณะเยาวชนเชิดจริงอยู่จนทุกวันนี้ เส้นทางในแอปมี ๒ จุด เดินตามลำดับ
คือ **พิพิธภัณฑ์หนังใหญ่** แล้วต่อด้วย **โรงมหรสพหนังใหญ่** จบที่การเปิดให้จองรอบเวิร์กช็อป

> นี่คือ **ต้นแบบสำหรับสาธิต** ไม่ใช่ระบบใช้งานจริง — ไม่มี backend ไม่มีฐานข้อมูล ไม่มีระบบล็อกอิน
> ไม่มีการชำระเงินจริง และ **ไม่เปิดกล้องจริง** ข้อมูลทั้งหมดเป็น mock เก็บใน `localStorage` ของเครื่องนั้น

## วิธีรัน

```bash
npm install
npm run dev
```

เปิด `http://localhost:5173` — **ไม่ต้องใช้ API key และไม่ต้องตั้งค่า environment variable ใด ๆ**

```bash
npm run build && npm run preview   # ทดสอบเวอร์ชัน production
```

### Deploy บน Vercel

มี `vercel.json` เตรียมไว้แล้ว: rewrite ทุกเส้นทางไปที่ `index.html` และส่ง header
`Permissions-Policy` ที่อนุญาต `geolocation` ให้โดเมนตัวเอง

1. push โค้ดขึ้น GitHub
2. ที่ Vercel เลือก **Add New → Project** แล้วเลือก repo นี้
3. ค่าที่ Vercel ตรวจจับเองถูกอยู่แล้ว: Framework `Vite` · Build `npm run build` · Output `dist`
4. กด **Deploy** — **ไม่ต้องตั้ง environment variable ใด ๆ**

หรือใช้ CLI: `npx vercel` / `npx vercel --prod`

## เส้นทางการสาธิต (ประมาณ ๓ นาที)

1. **หน้าแรก** — การ์ดสถานที่ที่เปิดให้เล่น AR แล้ว ตอนนี้มีวัดขนอนที่เดียว
   ที่เหลือขึ้นเป็นรายการ “กำลังจะเปิดเร็ว ๆ นี้”
2. **หน้าสถานที่** — เรื่องของวัด ไฮไลต์ และลำดับจุดในเส้นทาง จบด้วยปุ่ม **“เริ่มเส้นทาง AR”**
3. **แผนที่ในวัด** — หมุด ๒ จุดบนแผนที่วัด เดินตามลำดับ จุดที่ ๒ จะล็อกไว้จนกว่าจุดแรกจะจบ
   แถบล่างบอกว่ายังห่างจากจุดอยู่กี่เมตร ปุ่มเริ่มสแกนจะกดได้ก็ต่อเมื่อ **เข้าใกล้จริงในระยะ ๖๐ เมตร**
   ถ้าสาธิตอยู่ในห้อง ให้กด **“โหมดสาธิต: จำลองว่าถึงจุดนี้”** ใต้ปุ่ม
4. **จุดที่ ๑ พิพิธภัณฑ์** — สแกนป้าย → ลุงวิรัชโผล่มาเล่าที่มาของหนังใหญ่ → พาเดินเข้าไปในพิพิธภัณฑ์
   → บอกให้สแกนตัวหนังชุดพระนครไหว → ตัวหนังลอยออกมาจากป้าย **ลากเล่นได้**
   → ถ่ายรูปคู่กับตัวหนัง เลือกกรอบ แล้วแชร์หรือเก็บไว้ → ลุงพาไปต่อที่โรงมหรสพ
5. **จุดที่ ๒ โรงมหรสพ** — สแกนหน้าโรง → ลุงอธิบายว่าหนังใหญ่ต่างจากหนังตะลุงอย่างไร
   → เข้าไปข้างใน สแกนเวที → เห็นการเชิดหลังจอ
6. **จบเส้นทาง** — แผงจองรอบเวิร์กช็อป “ฝึกเชิดหนังใหญ่กับปราชญ์วัดขนอน” เด้งขึ้นเอง
   เลือกรอบ ยืนยัน แล้วได้หมายเลขจองที่กลับมาดูหรือยกเลิกได้

## หน้าจอและเส้นทางใน URL

| เส้นทาง | หน้าจอ |
|---|---|
| `/` | หน้าแรก — ฟีดสถานที่ที่เปิดให้เล่น AR |
| `/place/:placeId` | รายละเอียดสถานที่ + ปุ่มเริ่มเส้นทาง AR |
| `/place/:placeId/map` | แผนที่ในสถานที่ พร้อมหมุดจุดตรวจตามลำดับ |
| `/place/:placeId/journey/:checkpointId` | ตัวเล่นเส้นทางของจุดนั้น (เต็มจอ) |

## เส้นทางเขียนอย่างไร

หนึ่งจุดตรวจ = รายการ **beat** เรียงกัน ใน `src/data/places.js`
ตัวเล่นใน `src/pages/Journey.jsx` เดินไปทีละ beat และ beat แต่ละชนิดบอกว่าจอต้องทำอะไร

| ชนิด | ทำอะไร |
|---|---|
| `scan` | รอให้ผู้ชมกดสแกนภาพจุดนั้น |
| `narrate` | ปราชญ์เล่าทีละบรรทัดทับภาพฉาก |
| `reveal` | ภาพฉากเปลี่ยน แล้วตัวหนังลอยออกมา ลากได้ |
| `photo` | เก็บตัวหนังไว้ เพิ่มกรอบ แล้วบันทึกหรือแชร์ |
| `show` | คณะเชิดแสดงหลังจอ สลับเฟรมไปเรื่อย ๆ |
| `done` | จบจุดนี้ — ไปจุดถัดไป หรือเปิดแผงจองถ้าเป็นจุดสุดท้าย |

เพิ่มจุดแวะในเส้นทาง = เพิ่ม object ในลิสต์ ไม่ต้องเขียนคอมโพเนนต์ใหม่

ทุกบรรทัดที่ปราชญ์พูดมีฟิลด์ `pose` กำกับ ซึ่งชี้ไปที่ภาพนิ่งท่าทางหนึ่งใน
`public/kanon/narrator/` — **นั่นคือแอนิเมชันทั้งหมดของตัวละครนี้** คือภาพนิ่ง ๑๐ ท่า
ที่ตัดจากภาพแผ่นเดียว แล้วสลับกันตามบท

## ภาพประกอบทั้งหมด

อยู่ใน `public/kanon/` ทั้งหมด ไม่มีการเรียกไฟล์จากภายนอก

| โฟลเดอร์ | เนื้อหา |
|---|---|
| `scene/` | ภาพถ่ายสถานที่จริงแต่ละฉาก + ภาพแผนที่ในวัด |
| `narrator/` | ปราชญ์ชุมชน ๑๐ ท่าทาง (`wai`, `explain`, `think`, `point…`, `thumbs_up`) |
| `puppet/interact.png` | ตัวหนังใหญ่ชุดพระนครไหว ที่ลอยออกมาจากป้ายและลากเล่นได้ |
| `puppet/show_1..4.png` | คนเชิด ๔ เฟรม ใช้วนเป็นการแสดงหลังจอ |

ภาพท่าทางของปราชญ์ทุกใบถูกจัดให้ **ลำตัวอยู่ตำแหน่งเดียวกัน** ก่อนบันทึก
ไม่อย่างนั้นเวลาสลับท่าที่กางแขน ตัวคนจะกระโดดไปมาแทนที่จะขยับแค่แขน

## เก็บข้อมูลที่ไหน

ทุกอย่างผ่าน `src/lib/storage.js` ที่เดียว — ห่อ `localStorage` ไว้เป็น JSON ก้อนเดียว
พร้อม pub/sub เล็ก ๆ ให้ React re-render เมื่อมีการเขียน

```
{ theme, progress: { [placeId]: { done: [...], beat: {...} } }, photos: [...], bookings: [...] }
```

ถ้าจะต่อ backend จริงในอนาคต เปลี่ยนแค่ `read()` / `write()` ในไฟล์นี้ไฟล์เดียว

## สิ่งที่ต้นแบบนี้ตั้งใจ "ไม่ทำ"

- **ไม่เปิดกล้องจริง** — "ภาพจากกล้อง" ในหน้าสแกนคือ **ภาพถ่ายของจุดที่ผู้ชมกำลังยืนอยู่หน้ามัน**
  ไม่มี `getUserMedia` ไม่มี computer vision และไม่มีการตรวจจับวัตถุใด ๆ
  การกดสแกนคือการเดินบทไปข้างหน้า — ข้อดีคือเส้นทางทั้งหมดทำงานได้แม้ออฟไลน์บนเครื่องที่ยืมมา
- **ไม่มี backend / ฐานข้อมูล / ระบบล็อกอิน** — ข้อมูลอยู่ในเครื่องผู้ใช้เท่านั้น
- **ไม่มีระบบชำระเงินจริง** — การจองรอบเวิร์กช็อปแสดงราคาไว้เพื่อให้เห็นภาพ
  แต่ไม่มีการเชื่อมต่อผู้ให้บริการชำระเงินและไม่มีการตัดเงิน มีป้ายกำกับไว้ในแอปชัดเจน
- **ไม่ใช่ภาพเคลื่อนไหวจริง** — ทั้งปราชญ์และคณะเชิดคือภาพนิ่งหลายใบที่สลับกันตามจังหวะบท

## หมายเหตุเรื่องภาพแผนที่

ไฟล์แผนที่ที่ใช้อยู่ (`public/kanon/scene/map.jpg`) มีหัวเรื่องว่า
**“แผนที่วัดหนองรางวัดขนอน อ.วิเศษชัยชาญ จ.อ่างทอง”** ซึ่งเป็นคนละวัดกับวัดขนอน จ.ราชบุรี
ที่เส้นทางนี้เล่าถึง ในต้นแบบใช้เป็นภาพแทนไปก่อนเพื่อให้เห็นกลไกหมุดและลำดับจุด
ถ้าจะนำไปใช้จริงต้องเปลี่ยนเป็นแผนผังของวัดขนอน ราชบุรี แล้วแก้ค่า `pin: { x, y }`
(หน่วยเป็นเปอร์เซ็นต์ของภาพ) ของจุดตรวจทั้งสองใน `src/data/places.js`
