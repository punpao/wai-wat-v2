# วัยวัฒน์ (Wai-Wat) — AR Wisdom Trail

ต้นแบบ (prototype) สำหรับ **Moral Hackathon 2026** — แอปเดินสำรวจสถานที่จริงแบบ Pokémon GO
แต่สิ่งที่ตามหาคือ **ผู้เฒ่าและเรื่องเล่าประจำย่าน** ไม่ใช่มอนสเตอร์

เมื่อผู้สำรวจเดินไปถึงจุดตรวจ (checkpoint) จะเปิดกล้องสแกนหา “ผู้เฒ่า” ที่ปรากฏขึ้นในโหมด AR
แล้วเล่าความรู้ที่ผูกกับสถานที่นั้นให้ฟัง ส่วนผู้เฒ่าที่เล่าเรื่องจะได้ **แต้มภูมิปัญญา**
ซึ่งนำไปแลกบริการสวัสดิการในชีวิตจริงได้ เช่น พาไปโรงพยาบาล หรือตัดผมถึงบ้าน

> นี่คือ **ต้นแบบสำหรับสาธิต** ไม่ใช่ระบบใช้งานจริง — ไม่มี backend ไม่มีฐานข้อมูล ไม่มีระบบล็อกอิน
> ข้อมูลทั้งหมดเป็น mock และเก็บไว้ใน `localStorage` ของเบราว์เซอร์เครื่องนั้น

---

## วิธีรัน

```bash
npm install
npm run dev
```

เปิด `http://localhost:5173` — **ไม่ต้องใช้ API key และไม่ต้องตั้งค่า environment variable ใด ๆ**
ใช้ได้ทั้งบนเบราว์เซอร์เดสก์ท็อปและมือถือ

```bash
npm run build && npm run preview   # ทดสอบเวอร์ชัน production
```

> **หมายเหตุเรื่องแผนที่:** ชั้น “แผนที่จริง” ดึงภาพแผนที่จาก OpenStreetMap จึงต้องต่ออินเทอร์เน็ต
> ถ้าเน็ตถูกจำกัด แอปจะขึ้นข้อความแจ้งและยังกดจุดตรวจได้ตามปกติ — หรือสลับไปชั้น
> **“นักสำรวจ”** ซึ่งวาดเองทั้งหมดและทำงานได้แม้ออฟไลน์

## โหมดสาธิต (Demo Mode) — สิ่งที่ต้องรู้ก่อนนำเสนอ

กรรมการจะไม่เดินไปยังพิกัด GPS จริงระหว่างตัดสิน จึงมี **โหมดสาธิต** ให้จำลองการเข้าใกล้จุดตรวจได้ทันที

**ปุ่ม “โหมดสาธิต”** อยู่มุมขวาล่างของทุกหน้าในบทบาทผู้สำรวจ กดแล้วจะได้:

| สิ่งที่ทำได้ | ผลลัพธ์ |
|---|---|
| **ฉันอยู่ใกล้ \<ชื่อจุด\>** | ย้ายตำแหน่งจำลองไปข้างจุดนั้น แล้วเปิดหน้าสแกน AR ทันที |
| **ใช้ GPS จริง / ล้างตำแหน่งจำลอง** | สลับระหว่างพิกัดจริงกับพิกัดจำลอง |
| **รีเซ็ตข้อมูลทั้งหมด** | ล้าง `localStorage` เพื่อเริ่มสาธิตรอบใหม่ |

อีกทางหนึ่ง: แตะจุดตรวจบนแผนที่ แล้วกดปุ่ม **“โหมดสาธิต · จำลองว่ายืนอยู่ตรงนี้”** ในการ์ดข้อมูลจุดนั้น

**สลับบทบาท** ผู้สำรวจ ⇄ ผู้เฒ่า ได้จากปุ่มมุมขวาบนของหัวแอป — เป็นความสะดวกในการสาธิตเท่านั้น ไม่ใช่ระบบยืนยันตัวตน

---

## เส้นทางการสาธิตที่แนะนำ (ประมาณ 3 นาที)

1. **แผนที่** — เลือก “เชียงใหม่ · ย่านเมืองเก่า” จากรายการ แผนที่จะบินไปที่จุดตรวจ
2. สลับปุ่ม **แผนที่จริง ⇄ นักสำรวจ** เพื่อให้เห็นว่าเป็นข้อมูลชุดเดียวกันคนละสไตล์
3. แตะบ้านหลังใดก็ได้ → อ่านคำแนะนำของสถานที่ → กด **“จำลองว่ายืนอยู่ตรงนี้”**
4. **หน้าสแกน AR** — อนุญาตให้ใช้กล้อง แล้วกดปุ่มตามทิศที่ขึ้น (“ซ้าย!”, “ขวา!”, “ข้างหลัง!”)
   สัญญาณจะร้อนขึ้นเรื่อย ๆ จนพบผู้เฒ่า *(ถ้าไม่เปิดกล้อง จะใช้พื้นหลังจำลองแทนและขั้นตอนอื่นยังทำงานปกติ)*
5. ฟังคลิปจนจบ → ระบบบันทึกการค้นพบและให้แต้ม
6. **โปรไฟล์** — ดูสถิติ เหรียญตรา และประวัติ → กด **“ส่งกำลังใจ”** พิมพ์ข้อความแล้วส่ง
7. สลับเป็นบทบาท **ผู้เฒ่า** → เลือก “ยายลำไย ดอกไม้” ในกล่องท้ายหน้าหลัก → เปิด **คลิปของฉัน**
   จะเห็นข้อความที่เพิ่งส่งไปเมื่อครู่ปรากฏอยู่จริง
8. **แลกแต้ม** — แลก “ตัดผมที่บ้าน” แล้วดูหน้ายืนยันและสถานะคำขอ

---

## บทบาทและหน้าจอ

**ผู้สำรวจ (User)**
- **แผนที่** — เลือกย่านจากรายการ, จุดตรวจเป็นไอคอนบ้าน, แตะเพื่อดูคำแนะนำ, สลับได้ 2 ชั้นแผนที่
- **สแกน AR** — กล้องจริงผ่าน `getUserMedia` + คำใบ้ทิศทางจำลอง + ผู้เฒ่าปรากฏพร้อมคลิปความรู้
- **โปรไฟล์** — จำนวนจุดที่ค้นพบ, สถิติต่อเนื่อง, ระดับ, เหรียญตรา, ประวัติที่ฟังซ้ำได้,
  ส่งกำลังใจพร้อมข้อความ และแชร์ต่อทาง LINE

**ผู้เฒ่า (Elder)** — หน้าจอชุดนี้ตั้งใจออกแบบให้ **ตัวใหญ่ขึ้น คอนทราสต์สูงขึ้น ปุ่มกดง่ายขึ้น และมีแค่ 3 แท็บ**
- **หน้าหลัก** — แต้มคงเหลือ, สถิติผู้ฟัง, กำลังใจล่าสุด
- **คลิปของฉัน** — คลิปที่เล่าไว้ พร้อมจำนวนคนฟัง ถูกใจ และข้อความจากผู้ฟัง
- **แลกแต้ม** — แลกบริการสวัสดิการ พร้อมหน้ายืนยันและสถานะคำขอ

## แก้ไขข้อมูลจำลอง

ข้อมูลทั้งหมดอยู่ในโฟลเดอร์เดียว: `src/data/`

| ไฟล์ | เนื้อหา |
|---|---|
| `locations.js` | ย่าน/เส้นทาง, จุดตรวจ (lat/lng), คำแนะนำ, และคลิปความรู้ของแต่ละจุด |
| `elders.js` | ผู้เฒ่าแต่ละท่าน พร้อมสีของตัวละครที่ใช้วาดภาพประกอบ |
| `rewards.js` | รายการบริการที่แลกได้, เหรียญตรา, และเกณฑ์ระดับ |

เพิ่มจุดตรวจใหม่ = เพิ่ม object ใน `checkpoints` ของย่านนั้น แล้วจุดจะไปโผล่ครบทั้งสองชั้นแผนที่
รายการจุดตรวจ และแผงโหมดสาธิต โดยไม่ต้องแก้ที่อื่น

การอ่าน/เขียนข้อมูลทั้งหมดผ่าน `src/lib/storage.js` ที่เดียว (ห่อ `localStorage` ไว้)
ถ้าจะต่อ backend จริงในอนาคต เปลี่ยนแค่ไฟล์นี้ไฟล์เดียว

## สิ่งที่ต้นแบบนี้ตั้งใจ "ไม่ทำ"

- **ไม่มี backend / ฐานข้อมูล / ระบบล็อกอิน** — ข้อมูลอยู่ในเครื่องผู้ใช้เท่านั้น
- **ไม่ใช่ AR ด้วย computer vision จริง** — เป็นภาพจากกล้อง + UI ซ้อนทับ + ตัวละคร 2D
  คำใบ้ทิศทางเป็นค่าจำลอง ไม่ได้ติดตามวัตถุจริง
- **ไม่ใช้ LINE Messaging API** — ปุ่มแชร์ใช้ LINE share URL scheme ซึ่งไม่ต้องมีเซิร์ฟเวอร์หรือ API key
  ถ้าเปิดไม่ได้จะคัดลอกข้อความให้แทนพร้อมแจ้งเตือน
- **ไม่ใช่แผนที่ 3 มิติจริง** — ชั้น “นักสำรวจ” คือการวาดข้อมูลชุดเดิมด้วย SVG ในสไตล์เกม
